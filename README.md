# KurumiAIUserbot

[![CI](https://github.com/kurumiZafkiel12/KurumiAIUserbot/actions/workflows/ci.yml/badge.svg)](https://github.com/kurumiZafkiel12/KurumiAIUserbot/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

一个跑在 **Telegram 个人账号**（userbot，不是 Bot API 机器人）上的 AI 聊天机器人。

它登录你的一个 Telegram 小号，监听私聊和群聊消息：私聊里直接发消息就能问，群里 `@` 它或回复它的消息提问，它就调用你配置的 AI 接口（OpenAI 兼容格式）流式生成回答，并把答案编辑回占位消息里。支持多个模型接口按权重轮换、失败自动切换、每日限额防刷，以及一组号主管理命令。

这份文档是**给零基础准备的实操版**：从「要准备什么」开始，一步一步把命令写全，照着敲就能跑起来。

> ⚠️ userbot 用的是真人账号登录态，违反 Telegram 使用习惯的用法有封号风险。请务必使用**小号**，不要用你的主账号跑。

## 功能列表

- 私聊、群聊都能用：私聊直接发消息即可（不用 @）；群里 `@机器人用户名 + 问题`，或**回复机器人发的消息**都能续聊
- 流式回复：先发一条「（思考中...）」占位消息，生成过程中分段刷新，完成后替换为完整答案；超长答案自动分片
- 上下文：按「会话 + 提问者」保存最近对话（默认 20 条），能接上话；号主可一键清空
- 多模型池：多个 OpenAI 兼容接口（官方、第三方中转、自建服务都行），按权重挑选、失败冷却并自动换下一个
- 每日限额：每个模型可设每日调用上限，跨天自动清零，防止额度被刷爆
- 号主命令：查状态/服务器/日志、查账单（含用量与 Token 统计）、API 管理（查看/换模型/限额/换 key/禁用/加接口，在线生效）、用户名触发开关、拉黑/限速、关键词与屏蔽群管理、设人设、增删管理员、一键全局关闭/开启
- 识图池：给聊天 API 加识图模型（按权重挑选）；发照片提问、或回复一张照片提问，自动用池里的模型识图
- 生图：加了生图 API 后，在聊天里说「画一张 …」就会生成图片发回来
- 语音与人格：接 TTS 接口后可按群开启「说」（回答后追加一条语音）；可维护音色库与音色人格（人格塑造说话风格），群友能自选音色
- 群聊天记录：指定群可开启消息记录，回答该群问题时带上最近的聊天记录作上下文，它知道大家在聊什么
- 联网搜索：配了搜索 key 后，问时效性问题会先联网搜索再回答（问题里带「联网搜索」走深度搜索）
- 内置工具（免 Key）：聊天时直接说，模型会自己调用工具——查天气、翻译、百度/微博/抖音/B站热榜、汇率换算、加密货币价格、金价、油价、电影票房、豆瓣电影、维基百科/维基数据/DuckDuckGo、IP 归属、一言、今日诗词、图书查询、GitHub 仓库搜索、世界时间、黄历、星座运势、塔罗、抽签、掷骰子、抛硬币、二维码生成、短网址还原、Base64/URL/摩斯编解码、哈希、JSON 格式化、进制转换、单位换算、日期计算、随机数、密码生成、字数统计、颜色换算、设定时提醒、待办清单；语音朗读自带 Edge TTS 默认音色，没配 TTS 接口也能出声（提醒与待办存 reminders.json，重启不丢）
- 破甲与安全：可设最高优先级「破甲」（只存本地配置、不进仓库）；系统提示末尾有身份核验断言（只给结论不给 ID）；所有回复都过出口脱敏，配置里的 key 绝不出现在回复中
- 分条发送：设了人设时，闲聊回复会按行拆成多条逐条发，像真人打字；专业长答和命令回复保持整条
- 群内命令：号主在群里 `@机器人用户名 /ai 命令` 也能执行号主命令
- 权限体系：创建者（认 ID 认主）/ 管理员 / 普通用户三档；可开启「仅管理员可私聊」门禁
- 记事本与用户档案：每个会话有一份能跨重启的事实记事本（聊多了自动整理）；谁说「叫我 X」就记住他的称呼，还会慢慢攒下对每个人的印象来调整语气（详见下方「记事本与用户档案」）
- 黑名单：被拉黑的用户提问一律不理；名单保存在 config.json 里，重启不丢
- 防刷冷却：普通用户两次提问至少间隔 5 秒（可配）
- 名字时钟（可选）：机器人显示名显示为「前缀 + 当前时间」，如 `GPT 13:45`，每分钟刷新，时区可配
- 日志：控制台 + 按天文件（`logs/bot-YYYY-MM-DD.log`），所有报错都进日志，不静默吞掉

## 你需要准备什么

先把这 4 样备齐，缺一样都会卡住。后面每一步会具体说怎么弄。

| # | 东西 | 数量 | 是什么 / 去哪弄 | 大概成本 |
|---|---|---|---|---|
| 1 | **VPS（云服务器）** | 1 台 | 一台 24 小时开机的远程 Linux 电脑，机器人住在上面。配置不用高：**1 核 CPU / 1 GB 内存 / 10 GB 硬盘**就够跑（单个机器人实测只占约 **50 MB 内存**，1 GB 的机器同时跑好几个号都够）；系统选 **Debian 12** 或 **Ubuntu 22.04**。买的时候商家会给你三样东西：**IP 地址、root 密码、SSH 端口**（端口一般是 22，改过端口的商家会单独写明），先记好 | 常见价位约 20～50 元/月（年付更便宜） |
| 2 | **Telegram 小号** | 1 个 | 专门用来当机器人的 Telegram 账号。**不要用你的大号**（有封号风险，见文末安全提醒）。提前在手机或电脑上登录好这个小号，因为登录时要收验证码；顺手给它设一个**用户名**（@xxx），别人靠这个 @ 它 | 已有小号就免费 |
| 3 | **能收验证码的 Telegram 应用** | 1 个 | 登录时验证码发到小号已登录的 Telegram 应用里（官方服务通知对话），一般不发短信。提前在手机/电脑上登好小号等着收码即可。**不用申请 api_id / api_hash**：程序内置了 Telegram Desktop 公开凭证，输手机号就能登 | 免费 |
| 4 | **AI 接口（API Key）** | 1 个 | 机器人回答问题靠它。要 **OpenAI 兼容格式**的接口都行：OpenAI 官方、国内/国外的中转服务、自建的接口都可以。你会用到三样：**key**（一串 `sk-` 开头的密钥）、**接口地址**（一般以 `/v1` 结尾）、**模型名**（如 `gpt-4o-mini`，以商家实际支持为准） | 按用量付费，中转一般先充几块到几十块就能用很久 |

另外你还需要**一台能上网的电脑**（Windows 或 Mac 都行）来敲命令；实在没有电脑，用手机装个 SSH 客户端（如 Termius）也能操作，就是打字累一点。

> 为什么要 VPS，不能装在自己电脑上？可以装，但你电脑一关机/一断网，机器人就下线了。想让它全天在线，就得放 VPS 上。本教程默认按 VPS 讲；装自己电脑上也行，跳过第 2 步，在本机终端里从第 3 步开始即可（Windows 本机跑不适用 systemd 那步）。

## 全程路线图

整个过程大概长这样，心里先有个数（熟练后全程约 20 分钟）：

1. **准备登录**（不用申请任何东西，小号能收验证码就行）
2. **连上 VPS**（约 3 分钟，学会用 SSH 登录服务器）
3. **装环境和代码**（约 5 分钟，装 Node.js、下载本项目）
4. **填配置 .env**（约 5 分钟，把凭证和 key 填进一个文件）
5. **首次登录**（约 3 分钟，输手机号 + 验证码，之后免登录）
6. **启动并测试**（约 2 分钟，用大号给它发条消息验证）
7. **让它 24 小时在线**（约 3 分钟，交给 systemd 托管，关掉终端也不停）

下面提到的「终端」「命令行」指的是同一个东西：一个能输入命令的黑框窗口。在 VPS 上操作时，你是先用 SSH 连进服务器（第 2 步），之后的命令都输在那个连接窗口里。

## 第 1 步：登录不用申请 API

以前的教程要先去 my.telegram.org 申请一对 api_id / api_hash 才能登录，又麻烦又容易卡。**现在不用了**：程序内置了 Telegram Desktop 公开凭证（就是官方桌面客户端开源代码里公开的那一对），登录时你只做一件事——**输手机号 + 验证码**，跟在官方应用里登录新设备一模一样。

两点要知道：

- 如果你已经有自己申请的凭证，想用自己的：在 `.env` 里填 `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` 即可覆盖内置的，不填就走内置。
- **同一个账号要一直用同一套凭证登录**，别今天用内置、明天换自己的——中途换凭证可能触发 Telegram 的发码限制。本项目生产在用的账号一直用的就是内置这套。

## 第 2 步：连上你的 VPS

买好 VPS 后，商家会给你 **IP 地址**、**root 密码**，多数还会给 **SSH 端口**（没写就默认 22）。连接 VPS 用的方式叫 SSH，在你自己的电脑上操作：

**Windows**：按 `Win + R`，输入 `powershell` 回车（或打开 Windows Terminal），在窗口里输入：

```bash
ssh root@你的服务器IP
```

如果商家给的端口不是 22（比如 25330），就加 `-p 端口`：

```bash
ssh -p 25330 root@你的服务器IP
```

**Mac**：打开「终端」（在启动台搜 Terminal），命令同上。

**手机**：装 Termius，新建连接，填 IP、端口、用户名 `root` 和密码即可。

第一次连接会发生这些事，都是正常的：

1. 出现一行 `Are you sure you want to continue connecting (yes/no)?` —— 输入 `yes` 回车。
2. 出现 `root@xxx's password:` —— 输入商家给的 root 密码再回车。**注意：输密码时屏幕上不会显示任何字符**（连星号都没有），这是 Linux 的正常行为，盲打完直接回车就行，别以为键盘坏了。
3. 登录成功后，提示符会变成类似 `root@debian:~#` 的样子。**从这里开始，后面所有命令都输在这个窗口里**，你操作的就是那台 VPS 了。
4. 想断开时输入 `exit` 回车。注意：直接关窗口也行，但第 6 步之前，机器人是跟着你的连接窗口活的，窗口关了它就停——所以才有第 7 步的 systemd 托管。

> 如果提示 `Permission denied`，多半是密码输错了（注意大小写、有没有多复制了空格），或者端口不对。再不行就去商家后台重置 root 密码。

## 第 3 步：装环境和代码

以下命令都在 VPS 的 SSH 窗口里一条一条输（每输完一条按回车，等它执行完再输下一条）。

先装两个基础工具（Debian / Ubuntu 通用）：

```bash
apt update && apt install -y git curl
```

装 Node.js 20（项目要求 Node 20 或更高）。用 NodeSource 官方源：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | bash -
apt install -y nodejs
node -v
```

最后一条 `node -v` 如果输出 `v20.x.x`（如 `v20.20.2`），说明 Node 装好了。

> 如果你的系统不是 Debian/Ubuntu，或者上面脚本报错，也可以去 https://nodejs.org 下载官方 Linux 二进制包，解压到 `/usr/local` 使用，效果一样。

下载本项目代码并安装依赖：

```bash
cd /opt
git clone https://github.com/kurumiZafkiel12/KurumiAIUserbot.git kurumiaiuserbot
cd kurumiaiuserbot
npm install
```

- `git clone` 是把代码下载到 `/opt/kurumiaiuserbot` 文件夹。
- `npm install` 是按项目清单把依赖包装好，需要等 1～2 分钟；看到 `added xxx packages` 就是装完了。中间滚过一堆文字是正常的，只要最后没有红色的 `npm error` 就行。
- 之后本教程所有命令都默认你在这个目录里（`/opt/kurumiaiuserbot`）。如果重连了 SSH，先 `cd /opt/kurumiaiuserbot` 回来再操作。

## 第 4 步：填配置 .env

项目用一个叫 `.env` 的文件存所有凭证。先复制一份模板出来：

```bash
cp .env.example .env
```

然后用系统自带的文本编辑器 nano 打开它：

```bash
nano .env
```

nano 的操作只需要记住三件事：**方向键**移动光标，直接打字就能改；改完按 `Ctrl + O` 再回车是保存；`Ctrl + X` 是退出。（屏幕底部有一排 `^O` 之类的提示，`^` 就是 Ctrl 键。）

把下面这些逐项改成你自己的（等号右边就是要填的值，不要加引号、不要留空格）：

| 变量 | 必填 | 填什么 |
|---|---|---|
| `TELEGRAM_API_ID` | 否 | 可留空（用内置 Telegram Desktop 公开凭证）。想用自己申请的 api_id 时填纯数字 |
| `TELEGRAM_API_HASH` | 否 | 可留空（同上）。填了 ID 就必须同时填这个 |
| `MY_USERNAME` | 是 | 机器人小号的用户名，不带 `@`。别人 `@` 这个名字就能触发它 |
| `OWNER_ID` | 是 | 你**大号的数字 ID**（不是用户名）。只有这个 ID 发出的号主命令才有效，填错了号主命令会完全没反应。查自己 ID 的办法：在 Telegram 里搜索并打开任意一个「查 ID」机器人（如 `@userinfobot`），给它发任意消息，它就会回复你的数字 ID |
| `AI_API_KEY` | 是 | 你买的 AI 接口的密钥，一般 `sk-` 开头 |
| `AI_API_BASE` | 是 | AI 接口地址，OpenAI 兼容格式，一般以 `/v1` 结尾，如 `https://api.openai.com/v1`，或你的中转服务给的地址。**结尾别多打空格，`/v1` 别漏** |
| `AI_API_MODEL` | 是 | 模型名，如 `gpt-4o-mini`，以你的接口实际支持的为准，名字写错会报错 |
| `TIMEZONE` | 否 | 时区，默认 `Asia/Shanghai`，影响名字时钟 |
| `NAME_PREFIX` | 否 | 名字时钟前缀，默认 `GPT`，显示成「GPT 13:45」 |
| `NAME_CLOCK` | 否 | `true` 开启名字时钟，`false` 关闭，默认开启 |

填好保存退出。`.env` 里全是密钥，不要截图发给任何人。

## 第 5 步：首次登录

让机器人小号在服务器上登录一次（只需这一次）：

```bash
npm run login
```

流程：

1. 程序会先醒目提示**手机号必须带国家区号**，然后让你输入小号的手机号。
   - 中国大陆：`+86` 开头，如 `+8613812345678`
   - 美国/加拿大：`+1` 开头，如 `+13825550137`
   - **区号填错，验证码会发到别人的账号上**，你这边永远等不到；之前就有人把 `+1` 的号码按 `+86` 输，码全发给了陌生人。
2. 输入手机号后，验证码**一般不走短信**，而是出现在 Telegram 应用里的 **“Telegram”官方服务通知对话**中。打开任意已登录该小号的客户端查看那串数字，回到终端输入。
3. 如果小号开了**两步验证**，接着输入两步验证密码（没开就直接回车）。
4. 整个过程必须**一口气在同一次运行里完成**：中途关掉终端重来，验证码会失效并报错 `PHONE_CODE_EXPIRED`。
5. 成功后会话会存到项目目录的 `.ai-session` 文件里。之后启动不用再输验证码，除非会话被 Telegram 注销。这个文件等于账号的钥匙，**千万不要外泄**。

## 第 6 步：启动并测试

```bash
npm start
```

看到日志 `登录成功：@xxx，开始监听消息...` 就是跑起来了。先别关窗口，拿你的**大号**做两个测试：

1. **私聊测试**：用大号给小号直接发消息：`你好`（私聊不用 @，直接发就能触发，见「使用方法」）。
2. **群聊测试**：把小号拉进任意一个群，在群里发 `@小号用户名 你好`，或者直接**回复它发的消息**提问。

它先回一条「（思考中...）」，几秒后原地变成答案，就是成功了。如果完全没反应，先按文末「常见问题排错」里的自查清单走一遍。

停止：在运行窗口按 `Ctrl + C`。注意这种方式启动的话，**关掉 SSH 窗口机器人也会停**——想让它全天在线，做下一步。

## 第 7 步：让它 24 小时在线（systemd）

systemd 是 Linux 自带的「托管服务」：让它开机自启、崩溃自动拉起、关掉你的 SSH 窗口也不受影响。新建服务文件：

```bash
nano /etc/systemd/system/kurumiaiuserbot.service
```

把下面内容原样粘贴进去（nano 里粘贴一般是右键或 `Ctrl + Shift + V`），保存退出：

```ini
[Unit]
Description=kurumiaiuserbot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/kurumiaiuserbot
ExecStart=/usr/local/bin/node src/index.js
Restart=on-failure
RestartSec=5
MemoryMax=400M

[Install]
WantedBy=multi-user.target
```

说明：`WorkingDirectory` 是项目目录，如果你没装在 `/opt/kurumiaiuserbot` 就改成你的实际路径；`node` 的路径如果不确定，用 `which node` 查，查出来是 `/usr/bin/node` 就把 ExecStart 里改成那个。

然后依次执行：

```bash
sudo systemctl daemon-reload            # 让 systemd 读到新服务
sudo systemctl enable --now kurumiaiuserbot   # 设为开机自启，并立刻启动
sudo systemctl status kurumiaiuserbot   # 看状态：显示 active (running) 就是在跑
```

以后日常运维记住这 4 条就够了：

```bash
sudo systemctl restart kurumiaiuserbot  # 重启（改完 .env / config.json 后要重启才生效）
sudo systemctl stop kurumiaiuserbot     # 停止
sudo systemctl status kurumiaiuserbot   # 看状态
journalctl -u kurumiaiuserbot -f        # 实时看日志（排错就看这个；Ctrl+C 退出看日志，不影响机器人运行）
```

## 使用方法

### 提问（所有人）

- **私聊**：直接发消息就行，不用 @，写什么它答什么。
  例：私聊窗口里直接发 `北京今天天气怎么样`
- **群聊提及触发**：在群里发 `@机器人用户名 + 问题`
  例：`@gpt88886666 北京今天天气怎么样`
- **回复续聊**（私聊、群聊都行）：直接**回复机器人发出的任意一条消息**提问，就能接着上文聊，不用再 @ 它。
- **看帮助**：被触发时只发 `帮助`（或 `help`），机器人会直接回一份写死的使用帮助，不用等模型。
- **发图提问**：直接发一张照片并在图说里写问题（或先发照片、再回复那张照片提问）；前提是号主已用 `/ai 加识图` 建好识图池，没建池时会提示。
- **画图**：问题以「画一张 / 画个 / 生成图片 / 画一幅」等开头时走生图（需号主先加生图 API），例：`@机器人用户名 画一张 坐在窗边的猫`。
- **公开命令**：被触发时发 `/ai 账单`、`/ai 模型`、`/ai 人设` 可直接用（不走模型、秒回）。
- **语音小命令**（群里）：发 `音色列表`、`当前音色`、`换音色 <音色名>`（换音色需本群已由号主开启换音色）。
- 机器人会先回一条「（思考中...）」，生成完毕后原地替换成答案；接着追问能带上文。
- 只 @ 它、不写问题，它会提醒你补上问题。
- 提问太频繁会被冷却（默认 5 秒一次），冷却内的提问不回复。

### 号主命令（只有 OWNER_ID 本人可用）

号主命令只认 `/ai ` 前缀（如 `/ai 状态`），在私聊或群里发都行。群里也可以发 `@机器人用户名 /ai 状态` 这样带提及的写法（仅限号主，机器人会先剥掉提及再执行）。注意：只有以 `/ai ` 开头的才是命令；发 `@ai 状态` 不会被当成命令，也不会触发机器人。

### 权限体系

机器人认三档人，权限从高到低：

| 身份 | 谁 | 能干什么 |
|---|---|---|
| **创建者** | `.env` 里 `OWNER_ID` 填的那个数字 ID，全局唯一 | 全部号主命令；给模型交代身份时它认得出你就是创建者本人 |
| **管理员** | 创建者用 `/ai 加管理员 <用户ID>` 任命的人 | 普通提问照常；私聊门禁开启时仍可私聊。**不能**跑号主命令 |
| **普通用户** | 其他所有人 | 只能提问；私聊是否放行看下面的私聊模式 |
| **访客** | 创建者用 `/ai 加访客 <用户ID>` 放行的人（仍属普通用户） | 身份与普通用户相同，只多一项：私聊门禁开启时可以私聊 |

几个要点：

- **认主只认 ID**：机器人判断「谁是创建者」只看数字 ID 是不是等于 `OWNER_ID`，并会把这条规则告诉模型——别人改个一样的昵称冒充没用。
- **管理员名单存 config.json**（字段 `adminIds`），用命令增删立即生效、重启不丢；也可以停机后手工编辑 config.json 再启动。
- **私聊模式**：config.json 里 `privateChat` 字段控制谁能私聊机器人：
  - `"all"`（默认）：人人可以私聊提问。
  - `"admins"`：只有创建者 + 管理员 + 访客能私聊，其他人的私聊消息会被静默忽略（日志里有记录）；**群聊不受影响**，群里照常能问。

  例：只想让自己和两个朋友私聊用，就在 config.json 里写 `"privateChat": "admins"`，再用 `/ai 加管理员 <朋友的用户ID>` 把朋友加上；只想放行私聊、不给管理员身份的话，用 `/ai 加访客 <朋友的用户ID>`。

### 一键开关（全局暂停）

创建者不在的时候，怕群友一直提问把 token 刷光、浪费钱？发一条 `/ai 关闭` 就行：

- 关闭后机器人进入**全局暂停**：所有人的提问（私聊、群聊、@ 提及）一律不回复、**不调用模型**，一分钱 token 都不花。
- 暂停期间**号主命令照常可用**（本来就只有创建者能发），随时发 `/ai 开启` 恢复；`/ai 状态` 里也能看到当前是开启还是关闭。
- 开关状态存在项目根目录的 `state.json` 里，**重启后保持关闭**，不会因为程序重启就自己恢复，得创建者亲手发 `/ai 开启` 才行。
- 暂停拦的是「除创建者外的所有人」，管理员也不例外；创建者本人暂停期间照常能用。

### 记事本与用户档案

光靠最近 20 条上下文，机器人记不住事：聊过的重要事情很快被新消息冲掉。这一节的两个机制就是给它补上「长期记忆」，都是自动的，不用配任何东西：

**事实记事本（按会话隔离，存 `facts.json`）**

- 每个会话（一个群 / 一段私聊）有一份自己的事实清单，最多 25 条，只在当前会话里用，不串场。
- 攒法有两种：号主用 `/ai 记住 <内容>` 手工加；另外**每答满 4 次**，机器人会在后台把「现有记事本 + 最近对话」交给模型重整一遍（合并同一个人的不同称呼、删掉过时或记错的、补上新事实），整个过程不耽误正常回复。
- 每次回答前，当前会话的记事本会作为系统备注发给模型，并交代它：被问到时用自己的话自然地讲，就像本来就记得一样，不许照抄条目、不许动不动报「这是谁说的」。
- 号主可以随时管理：`/ai 记事本` 看清单、`/ai 忘掉 <序号>` 删一条、`/ai 清空记事本` 全清。

**用户记事本（按用户 ID 隔离、跨会话通用，存 `userfacts.json`）**

- 每个用户（按数字 ID）有一份自己的事实清单，最多 25 条，**在所有群和私聊里通用**：在这个群聊到的关于他的事，换个群机器人照样记得他。
- 后台整理时模型会把事实分开归档：本会话的事进会话记事本，关于当前用户本人的事进他的用户记事本。
- 每次回答前，只把**当前说话人**的用户记事本发给模型（不会把别人的事漏给不相关的人），并交代它像本来就记得一样自然地讲。
- 号主管理：`/ai 查看印象 <用户ID>` 一并看他的称呼、印象与用户记事本；`/ai 忘掉用户 <用户ID> <序号>` 删一条；`/ai 清空用户记忆 <用户ID>` 全清。

**用户档案（按用户隔离，存 `profiles.json`）**

- **称呼**：任何人在自己的消息里明确说「叫我 X」（比如「以后叫我明哥」「不要叫我全名，叫我小李就行」），机器人就记住他的称呼，之后称呼他、转述他的话都用这个称呼，不再用显示名。识别规则很严：取最后一个「叫我」后的词，带否定（「不要叫我…」）或像提问的（「叫我干嘛」）都不记，宁可漏记不可记错。
- **印象**：后台整理记事本时，会顺带根据这个人最近的发言更新一两句对他的印象（说话风格、常聊话题、氛围、公开的日常小事，**不记隐私**）。印象只用来调整跟他说话的语气和熟络程度，交代过模型绝不念出来、绝不告诉别人。
- 群聊历史里的每条消息都带发言者标签（称呼优先，其次显示名），模型能分清谁是谁，不会把甲说过的话算到乙头上。

这些数据文件都在项目根目录下，重启不丢；想彻底忘掉，停机后删掉 `facts.json` / `userfacts.json` / `profiles.json` 再启动即可（已加入 `.gitignore`，不会误提交到仓库）。另外还有一个 `usage.json`：按天、按模型记的 Token 用量统计（供 `/ai 账单` 展示），跨天自动归零，同样不用管。

## 费用大概多少

- **VPS**：约 20～50 元/月（1 核 1G 的小配置足够；年付通常更便宜）。单个机器人运行内存约 50 MB（2026-11-15 在 1 GB 内存的 Debian 12 机器上实测，两个号各占 46～49 MB）。
- **Telegram 小号、api_id 申请**：免费。
- **AI 接口**：按你调用的量计费（按 token 量）。个人和群友日常聊天量不大，中转服务充个几块到几十块能用很久；记得在 config.json 里给模型设每日限额（`dailyLimits`），防止被人刷爆产生大额费用。
- 合计：最低成本就是一台 VPS 的月费 + 少量 API 余额。

## 常见问题排错

先记住一个通用方法：**机器人不对劲，先看日志**。日志在两个地方：运行窗口里滚动的输出，和项目目录 `logs/` 文件夹里按天存的文件（systemd 运行时用 `journalctl -u kurumiaiuserbot -f` 看）。所有报错都会写进日志，照着报错内容对下面的条目基本都能解决。

### 机器人完全不理人（先走这个自查清单）

1. 进程还活着吗？`sudo systemctl status kurumiaiuserbot` 看是不是 `active (running)`；不是就 `sudo systemctl restart kurumiaiuserbot` 再看日志报什么。
2. 触发方式对吗？群里必须 `@机器人用户名`，或**回复机器人发的消息**，两种方式之一才会触发，直接在群里说话它是不理的；私聊则不用触发方式，直接发消息就行（若私聊也不回，先查是不是开了「仅管理员可私聊」门禁或全局暂停）。
3. 是不是在冷却中？普通用户两次提问至少间隔 5 秒（可配），太急了它不回。
4. 号主命令没反应？先查 `.env` 里 `OWNER_ID` 填的是不是你**大号的数字 ID**（填成用户名或填了小号的 ID 都不行）。
5. 上面都没问题，就看日志里有没有报错，按下面对应条目处理。

### 私聊不回复，群里却正常（或反过来）

这是最经典的一个坑。Telegram 私聊消息走的是 `UpdateShortMessage` 简版更新：如果代码用 `client.addEventHandler(回调)` **裸注册**监听，回调里拿到的 `event.message` 不是完整消息对象（没有发送者、正文），私聊消息会被当作无效消息丢掉，看起来就是“私聊永远不回复，群里没事”。

本项目在 `src/index.js` 里用的是规范注册方式：

```js
import { NewMessage } from "telegram/events/index.js";
client.addEventHandler(handler, new NewMessage({}));
```

`NewMessage` 构建器会把简版更新统一转成标准消息对象，私聊和群聊走同一套处理逻辑。如果你魔改代码后出现“私聊不回”，先检查这里是不是被改回了裸注册。

### 发了问题，只停在“正在思考中”不动 / 没有任何回复

先看日志。常见原因：

- AI 接口报错（密钥错、地址错、模型名不存在、余额不足）：日志里有 `提供方 xxx 回答失败：...`，按报错修 `.env`。
- 每个提供方都失败时，占位消息会被改成“所有模型都暂时不可用”。
- 如果日志里出现 `ReferenceError: xxx is not defined` 这类错误，说明代码里有未定义的变量在“答案已生成、发送前”崩了——同类项目真实出现过这种 bug（计数变量没定义，回复永远发不出去而且表面无报错）。本项目已把计数状态收敛到类里管理并有单元测试覆盖；魔改后请先跑 `npm test`。

### 在群里不回复：USER_BANNED_IN_CHANNEL

日志里出现 `发送占位消息失败 ... USER_BANNED_IN_CHANNEL`，说明机器人号在**那个群里被禁言了**（群管理机器人自动禁言或管理员手动禁言都可能）。程序再怎么重试也发不出消息，只能找群管理解除禁言。另外 Telegram 官方的 @SpamBot 也可能对账号下**账号级限制**（新号 + 服务器 IP + 高频发消息容易触发），这种限制下私聊能回、群里发不出，和群禁言是两回事，要走 SpamBot 申诉或换号。触发点通常是：短时间频繁测试、反复发占位/编辑消息被当成刷屏。**测试时放慢频率，别拿新号在公开大群里高频刷。**

### 验证码收不到 / 发错区号

- 先确认手机号带了正确国家区号（`+86` / `+1` 等）。区号错了，码会发到**别人**账号上。
- 码一般在 Telegram 应用内的官方服务通知对话里，不在短信里。
- 发码后不要关终端重开登录脚本，同一次运行里完成验码，否则报 `PHONE_CODE_EXPIRED`。

### 提示会话失效

日志提示会话失效（`.ai-session` 不能用了），通常是小号在别处重新登录、改了密码或被 Telegram 注销会话。删掉 `.ai-session`，重新 `npm run login` 即可。

### 名字时钟不动了

- 确认 `.env` 里 `NAME_CLOCK=true`，且程序在正常运行（改名日志：`已更新显示名：GPT 13:45`）。
- 客户端里看到的名字可能有缓存，点进机器人资料页刷新再看。
- 同一分钟内不会重复改名；跨分钟才刷新。

### 命令相关的小问题

- 输命令提示 `command not found`：多半是命令输错了，或者还没装对应的东西（比如没装 Node 就输 `node -v`）。对照教程检查拼写和步骤顺序。
- `npm install` 报错：先确认在项目目录里（`pwd` 应显示 `/opt/kurumiaiuserbot`），且 `node -v` 是 20 以上；网络不通时多重试一次。
- nano 里改完不会保存：记住 `Ctrl + O` 回车保存、`Ctrl + X` 退出；退出时它问 `Save modified buffer?` 就按 `Y` 再回车。

## 安全提醒

- **只用小号跑**，不要用主账号。userbot 行为（自动回复、高频编辑消息）有被 Telegram 风控甚至封号的可能。
- **api_id / api_hash、`.ai-session`、`.env`、`config.json` 都不要外泄、不要提交到公开仓库**。`.ai-session` 泄露等于账号被别人登录；本项目已把它们都写进 `.gitignore`。
- 登录凭证：程序默认用内置的 Telegram Desktop 公开凭证（官方客户端开源代码里公开的那对），也可以在 `.env` 里填自己申请的覆盖。**关键是同一个账号固定用同一套**，别来回换。`.env` 里如果存了你自己的凭证，同样不要外泄、不要提交到公开仓库。
- AI 接口的密钥只放在 `.env` / `config.json` 里，不要写进代码、不要截图发出去。
- 给模型设每日限额（见 config.json 的 `dailyLimits`），避免被刷爆额度产生费用。
- 刚上线头几天别让它在公开大群里高频发言，新号 + 机房 IP 本来就是风控重点观察对象。
